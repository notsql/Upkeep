# App shell (frontend)

The root layout, header, home page and the conventions every feature file
below relies on. Paths are relative to `apps/web/src/`.

## Bootstrapping

| File | Role |
| --- | --- |
| `start.ts` | TanStack Start instance. Request middleware: CSRF (server functions only), then `authkitMiddleware()`. |
| `router.tsx` | `getRouter()` builds a **new `QueryClient` per router** (never module scope - SSR must not share caches). Default query `staleTime` 60s. Pending component `components/loader.tsx` (a shadcn `Spinner`, `role="status"` named "Loading"); not-found renders `Not Found`. Router context: `{ queryClient }`. |
| `routes/__root.tsx` | `<html>` document. Provider order: `ThemeProvider` (next-themes, class, default `dark`) > `AuthProvider` > `QueryClientProvider`. Layout grid: `Header` then `<Outlet />`. Also mounts `Toaster` (`@proj/ui/components/sonner`, `richColors`) and router devtools. |
| `routeTree.gen.ts` | Generated by the TanStack router plugin. Never edit. |

## Routes

| File | URL | Guard | Screen |
| --- | --- | --- | --- |
| `routes/index.tsx` | `/` | none | Home: ASCII banner and an "API Status" `Card`. |

Home query: key `["health"]`, `api.GET("/health")`, renders `data.ok` (API) and
`data.database` (Database) as up/down, "Checking..." with a decorative
`Spinner` while pending, or "API unreachable" in a destructive `Alert` on
error. shadcn: `Card` (`CardHeader`, `CardTitle`, `CardContent`), `Alert`,
`Spinner`.

## Header (`components/header.tsx`)

Rendered on every page. Nav links via TanStack `Link`:

| State (`useAuth()`) | Links |
| --- | --- |
| loading | Home only |
| signed out | Home, Register (`/register`) |
| signed in | Home, My estates (`/estates`), Account (`/account`) |
| signed in, `role === "admin"` | + Admin Dashboard (`/admin/users`) |

Right side: `EstateSwitcher` (see [estates.md](estates.md)) and `AuthButton`
(see [auth.md](auth.md)). A shadcn `Separator` divides the header from the
page.

## Conventions used by every feature

- **API client:** `lib/api.ts` exports `api` (`createApiClient` from
  `@proj/api`, base URL `VITE_API_URL`). The bearer token is resolved per
  request by `AuthTokenBridge` (browser only; SSR requests go unauthenticated).
- **Hooks live in `lib/<feature>.ts`.** Screens call those hooks. Exceptions
  that still call `api` inline are noted per feature (estate create/edit/
  deactivate, location writes, admin screens, home health check).
- **Session gate:** `useEstateSession()` (`lib/estates.ts`) returns
  `{ userId, ready }`; `ready` is true only after mount, once AuthKit has
  finished loading and a user exists. All estate-scoped queries use
  `enabled: ready` and `retry: false`.
- **Query keys** for per-user data start `["estates", userId, ...]`, so
  invalidating `["estates", userId]` clears one user's estate cache.
- **Errors:** `estateError(error, status)` turns an API error into an `Error`
  (401 gives a "sign in again" message, otherwise the API's `message`). Screens
  render `query.error.message` in a shadcn `Alert` (`variant="destructive"`,
  which carries `role="alert"`).
- **Loading:** visible text in a `role="status"` (or `aria-live`) paragraph
  with a decorative shadcn `Spinner` (`aria-hidden`), so only the text is
  announced.
- **Status pills** (Active/Inactive, condition, role tags) are shadcn `Badge`s;
  empty states use shadcn `Empty`.
- **Success feedback:** `toast.success(...)` from `sonner`.
- **Forms:** local `useState`/`FormData`, built from shadcn `Field`
  (`FieldSet` disabled while pending, `FieldLegend`, `FieldGroup`, `Field`,
  `FieldLabel`, `FieldError`); per-field errors are `FieldError`s wired to the
  control with `aria-invalid` + `aria-describedby`, and a save failure is a
  destructive `Alert`.

## Test imports

The web tsconfig maps `@/*` to `src/*` and `@tests/*` to `tests/*`. Vite and
Vitest use the same native tsconfig path resolution. Tests import application
code through `@/` and can import shared helpers through `@tests/test-utils`.
