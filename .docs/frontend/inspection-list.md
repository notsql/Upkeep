# Inspections screen (ID-84, ID-86)

API: [inspection-list.md](../api/inspection-list.md).

## Route

`/estates/$estateId/inspections` — `src/routes/_auth/estates/$estateId/inspections/index.tsx`
(title "Inspections") renders `-components/inspections-page/inspections-page.tsx`, which composes
`inspections-generation-status.tsx`, `inspections-no-flagged-categories.tsx` and
`inspections-checks.tsx`; `use-inspections-page.ts` holds queries and generation.

Entry: sidebar Maintenance › **Inspections**, shown by `canOpenInspections`
(`owned || canManageInvitationPermissions`); the `_auth` guard 404s otherwise. The item stays
active on `/inspections/schedules[/$interval]`.

Below the header, an "Inspection views" `SubNav` (`-components/inspection-views.tsx`, shared with
[check-schedules.md](check-schedules.md)): **Due checks** (exact, `/inspections`) and **Check
schedules** (`/inspections/schedules`).

## Data (`src/lib/inspection-list.ts`)

| Hook | Call | Query key / effect |
| --- | --- | --- |
| `useInspectionList(estateId, enabled = true)` | GET `/estates/{estateId}/inspection-list` | `inspectionListQueryKey(userId, estateId)` = `["estates", userId, "inspection-list", estateId]`; `retry: false` |
| `useGenerateInspectionList(estateId)` | POST `/estates/{estateId}/inspection-list/generate` | on success invalidates the list key |

Both throw `estateError(...)`. Recording permission comes from `useInspectionAccess(estateId).canCreate`
(`src/lib/inspections.ts`).

## Screen

`InspectionsPage`: `PageLayout` + `ListPageHeader` (no breadcrumbs or filters; description the month,
e.g. "November 2026"), then:

- **Summary cards** (`SummaryCard`, `src/components/page/summary-card.tsx`), each a region named by its
  title: **Overdue** (amber when above 0, "Missed in an earlier month"), **Due this month**,
  **Done this month**, and, only when there are unscheduled assets, **Not scheduled** (amber, with a
  **Set check schedules** link to `/estates/$estateId/inspections/schedules`).
- A **Generate list** button in the `ListPageHeader` `actions` (**Regenerate list** once `generatedAt` is set), disabled in an
  inactive estate or while pending. With `generatedAt`: "Last generated by <name> · <local
  date-time>" and "Regenerating adds newly due checks and never duplicates them."; without:
  "This month's list hasn't been generated yet." Success toasts "Added N checks." ("Added 1
  check.") or "No new checks are due."; failure shows a destructive `Alert`. An inactive estate
  shows a `role="note"` explanation.
- Checks grouped in the server's order: a `section` per block (an `h2` of the block name), and in
  it a `section` per level named "<Block>, <Level>" ("Block-wide" when `level` is null) with an
  `h3` and a `CheckTable` (`-components/inspections-page/check-table.tsx`). Columns: Asset ("<reference> · <name>"
  linked to the asset), Category, Due ("1 Oct 2026"), Basis ("Every 6 months (asset)", "Every 1
  year (category)", "Expected", "Never inspected"), Status (`Badge`: destructive **Overdue**, blue
  **Due**, green **Done · Pass/Fail**), and an unlabelled action column: **Record inspection**
  (ID-85's `/estates/$estateId/assets/$assetId/inspections/new`, only with `canCreate`) or **View
  result** (`/estates/$estateId/assets/$assetId/inspections/$inspectionId`) for Done.
  Below 768px (`useMobile`) each group is instead a `ul` labelled `Checks` of shadcn `Item`s
  (divided by `ItemSeparator`): title = asset name linked to the asset with the Status badge
  trailing; line 1 "<reference> · <category>"; line 2 "Due <date> · <basis>"; then the same
  end-of-life send action and Record inspection / View result links.
- When `flaggedCategoryCount` is 0, an `Alert` with `role="note"` and the accessible name "No
  flagged categories": "No equipment has regular checks turned on yet, so nothing is due." It has
  an outline **Turn on regular checks** link to `/estates/$estateId/inspections/schedules`. It is
  shown whether or not there are checks.
- The `EmptyState` "No checks this month" when there are none (description depends on whether
  the list was generated). Loading uses `LoadingState` "Loading inspections…". The sections stay
  stacked, not tabbed: Not scheduled assets is a short list shown only when non-empty.
- A **Not scheduled assets** section (`h2`) listing "<reference> · <name>" and the category label.

Loading shows "Loading inspections…"; a load error shows `ErrorState` with the
message and a Retry that refetches the list.

shadcn: `Card` (via `SummaryCard`), `Badge`, `Button`, `buttonVariants`, `Table`, `TableHeader`,
`TableBody`, `TableRow`, `TableHead`, `TableCell`, `Alert`, `AlertDescription`; `PageHeader` from
`src/components`.

## Design-system pass

ListPageHeader `icon={ClipboardCheck}`; "No checks this month" uses the
`ClipboardCheck` icon; Generate/Regenerate list has a leading
`ListPlus`. "No checks this month" descriptions: "Nothing due this month" /
"Generate the list to see due checks". Row View result / Record inspection links
are `ghost`.

## Sent checks and end-of-life rows (equipment dispatch)

`REQUESTED` checks show the basis "Sent to <person> by <manager>". Open
"Expected" rows whose equipment is flagged end of life also show "Send a
contractor" (`end-of-life-action.tsx`) to viewers who can create work orders.
See [equipment-dispatch.md](equipment-dispatch.md).
