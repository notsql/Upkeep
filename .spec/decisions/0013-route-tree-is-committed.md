# 0013 - The TanStack route tree is committed

**Status:** accepted

## Context

`apps/web/src/routeTree.gen.ts` is generated by the TanStack Start Vite plugin
from `apps/web/src/routes/`, and `router.tsx` imports it. The plugin only runs
inside Vite (`pnpm dev`, `pnpm build`); `tsc` never generates it.

The file was gitignored. That worked on every laptop that had run `pnpm dev`
once, but a fresh clone - and every CI run - has no route tree, so
`pnpm check-types` fails with `Cannot find module './routeTree.gen'` before
`pnpm build` ever gets the chance to create it.

## Decision

- **`routeTree.gen.ts` is committed**, like `packages/api/src/schema.ts` and the
  jOOQ classes (0002, 0008): a fresh clone and CI type-check without a
  generation step.
- **Biome ignores it** (`files.includes` in `biome.jsonc`). Biome previously
  skipped it only because it was gitignored (`vcs.useIgnoreFile`); without the
  exclusion, `pnpm fix` would reformat a file the plugin rewrites, forever.

Rejected: running `pnpm build` before `check-types` in CI (fixes CI, leaves
fresh clones broken, and delays type errors behind a full build), and adding
`@tanstack/router-cli` to generate it explicitly (a new dependency for the
same result).

## Consequences

- Adding, renaming or removing a route changes this file. Commit it with the
  route change - `pnpm dev` or `pnpm build` regenerates it.
- On a merge conflict in this file, do not hand-merge: take either side, run
  `pnpm dev` or `pnpm build`, and commit the regenerated file.
- Forgetting to commit it after a route change fails CI at `check-types`.
- Never hand-edit it; the plugin overwrites it.
